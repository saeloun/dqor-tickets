# Production public programme

The app opens the official published-only DQOR programme by default. The approved, deployed route is `GET https://deccanqueenonrails.com/api/public/v1/dqor/programme`, verified against the merged Rails route and contract. On 2026-10-03, an actual iPhone 17 Pro / iOS 26.5 simulator URLSession read returned 200 with schema 1, 34 sessions and 14 speakers; the next read using the exact weak ETag returned 304. These are observations of that publication, not fixed app content or promised counts.

`PublicProgrammeHTTPTransport` uses normal platform TLS, one fixed HTTPS URL, ephemeral URLSession, no cookies, credentials, authorization, URL cache or redirects. Requests and resources have 20/30-second limits. JSON bodies are limited to 2 MiB while streaming, including responses without a declared length. No private attendee, ticket or staff endpoint is called.

`PublicProgrammeClient` replaces the entire snapshot on each successful 200, including empty arrays and withdrawn sessions/speakers. Nullable scheduling stays nullable; the UI never invents durations or assigns unscheduled rows to a day. Times use the event timezone rather than the device timezone. Text is plain display text. Exact ETags, including weak markers and quotes, are retained; a matching cached snapshot is required for 304, and a conflicting returned validator is rejected. A cacheless 304 retries once unconditionally. Unsupported schemas, malformed data, server errors and offline failures preserve an existing snapshot and expose it as potentially outdated. Foregrounding revalidates, and retry is explicit while the programme is unavailable.

The programme snapshot and validator remain in memory. Cold offline launch shows an unavailable state. Only opaque published-session bookmark IDs persist in a separate local preference; authoritative replacement prunes withdrawals. Demo bookmarks use a separate in-memory store. Clear removes snapshot, ETag and persisted bookmarks, cancels the UI request, resets schedule filters/search, and invalidates late responses. Automatic foreground refresh remains paused after clear until the user explicitly loads the programme. A new explicit load can start while an old transport ignores cancellation.

The production home retains bundled original DQOR artwork, warm/plum colors, Dynamic Type and reduced-motion behavior. Programme search, day filters, saved sessions, nullable times, expandable details, empty/error/loading/stale states and Back navigation use actual published data. Initial loading, error and cleared states omit the large artwork so the primary load action remains promptly reachable.

`--public-fixture` in Debug selects clearly labeled synthetic public data; `--public-offline` starts that fixture disconnected. Synthetic response controls rehearse 200, 304, offline, 503, withdrawal and delayed responses. They are absent from Release and never change the live server. `--demo` explicitly launches the separate staff/design rehearsal; the production home also links to that labeled demo. Synthetic passes never appear as live credentials.

PR #189 is merged and deployed at main `6842a5b0b6224f24f78332593aff3b9b56d62be8`, with its account/pass cookie-authenticated JSON surface still disabled by default. That cookie contract is separate from undeployed draft PR #192's revocable native PKCE bearer lane. The iOS client now implements that draft behind a fixed closed production gate, with Debug-only synthetic account journeys and in-memory intercepted HTTP tests. The owner-approved canonical client/callback mapping still requires registry provisioning and verified domain associations; real native authentication is unavailable. There is no scannable native pass API. Production provides system-browser links to the existing official `/account` and `/tickets/mine` routes. Native networking neither reads nor copies browser cookies/tokens. Tests do not submit ticket-access or consent forms, send email or call private production endpoints. See [NATIVE_ATTENDEE_AUTH.md](NATIVE_ATTENDEE_AUTH.md) for contract and activation gates.

Staff credentials, native tokens and attendance writes remain disabled. See [README.md](README.md), [NATIVE_ADAPTER.md](NATIVE_ADAPTER.md) and [NATIVE_CONTRACT_REQUIREMENTS.md](NATIVE_CONTRACT_REQUIREMENTS.md) for the distinct approval and device gates.
