## Acceptance criteria

1. Existing authorized event managers can open a website editor from their event, save a draft, view an authenticated saved-draft preview, explicitly publish it and restore one prior publication. Viewers may read permitted drafts/previews but cannot mutate. Membership revocation and event/organization scoping are checked fresh for every read/write. Global staff/admin identity grants no tenant permission.
2. Event-owned website setting/asset tables are additive and unique per event. Existing DQOR singleton records, commerce, sessions, native contracts and global feature flags are untouched. No provisioning, grants, historical backfill or automatic enrollment of DQOR.
3. Server allowlists accept only the existing three theme directions, validated six-digit colors, preset heading fonts, managed logo/cover/favicon slots, bounded escaped text, bounded section order/visibility and internal navigation targets. Hero/about/venue content plus bounded manual programme/sponsor content are editable. Prefer a small useful plain form over a generic CMS. Reject arbitrary HTML/CSS/JS, remote image URLs, unknown fields and foreign asset IDs. Event title/dates/timezone remain existing canonical Event fields.
4. Reuse the existing raster normalization: PNG/JPEG/WebP signatures, at most1MB input/output, decoded dimension/pixel limits, no animation/SVG, metadata stripping. Draft assets require membership and private/no-store headers. Public assets require a published Event and the CURRENT published website snapshot referencing that same event-owned asset; draft/previous/cross-event/unpublished assets return404. No public signed ActiveStorage draft URLs.
5. Draft edits never affect the public page. A public configured Event page renders only its published snapshot with correct event identity and free-registration behavior. Unconfigured events retain functional existing pages. Tenant public headers/titles become event/organization-owned rather than hardcoded DQOR. Global Talk/Sponsor records never supply tenant content. DQOR root, tickets, invoices, attendee directory and scanner behavior stay unchanged.
6. Row locks plus lock_version reject stale save/publish/restore; failed validation/upload leaves saved/public snapshots unchanged. Current/prior publication images remain available for rollback. Document any pruning of superseded unreferenced website-only assets; do not touch existing DQOR assets. No destructive production rollback or automatic data deletion is performed.
7. Desktop and320/390px public/editor/preview journeys show readable content, keyboard labels/focus/skip navigation, reduced motion and no horizontal overflow. Foreground is derived for at least4.5:1 contrast on configured surfaces/accents. No arbitrary font names or external CSS/scripts are accepted.
8. Test cross-org/event reads/writes/assets, viewer/staff/anonymous denial, revoked membership, CSRF, malformed schema/uploads, publication isolation, rollback/stale writes and actual synthetic browser edit-preview-publish flows. Run migration up/down/reapply only on disposable local data, focused tests, production assets build, lint/security scan and full suite. Five independent experts approve before commit. Ready draft PR/evidence goes to parent for merge/deploy approval.
