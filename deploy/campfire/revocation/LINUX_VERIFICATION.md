## Results

`verify_sockets.rb` passed actual HTTP/multiple-WebSocket scenarios for logout,
membership removal, role downgrade and ban. Both affected sockets close and receive
no later message; an unaffected observer keeps receiving. Old-cookie/stream replay
fails after logout, membership removal and ban; downgraded admin HTTP access is 403.
See `evidence/linux-candidate.txt`. This is exact candidate execution, not macOS evidence.

`verify_adversarial.rb` loads the actual patched Driver, Frame and Cable under CRuby.
Its FFI adapter uses real socket pairs. It deterministically fails these contracts:

- An identity resolved before revocation cannot register a live socket afterward.
- A reconnect between the pre-commit ban disconnect and transaction completion is
  retired by the completed ban. This invokes the actual Campfire ban method with a
  controlled committed-state seam; it does **not** certify real SQLite isolation.
- Revocation completes within 500ms when an already-full peer never reads.

The affected-socket, unaffected-user and cleanup controls pass. See
`evidence/adversarial-linux-source.txt`. The script exits 1 for these failures.

`verify_backpressure_native.rb` additionally compiles the actual Driver/Frame through
the pinned Spinel compiler and links the retained native socket runtime. It fills a
real loopback TCP send buffer, signals after the writer acquires the driver's lock,
and attempts revocation. The revoker is still blocked after 500ms; closing the peer
releases both threads. It exits 1, not timeout. See
`evidence/backpressure-linux-native.txt`. The fixture is not the full server and makes
no scheduler performance claim, but confirms the deadlock-prone lock ordering exists
in native Linux execution, independently of the CRuby adapter.

## Reproduction commands

Use only disposable paths under `/tmp/dqor-campfire-revocation` and the public pins
from `provenance.json`. Download only the named artifact from the exact run:

```sh
gh run download 36983264271 --repo rubys/roundhouse \
  --name campfire-archive --dir /tmp/dqor-campfire-revocation/upstream-artifact
```

Validate archive hashes and reject absolute/traversal/link entries before extraction.
Generate the candidate as in README. Invoke the pinned compiler with the same `-I`
package and `--rbs` paths as the native build, adding `-c -o candidate.c`; C emission
needs no host object links. Copy the retained pack to a fresh build directory and
replace only `src/campfire.c`. Use the digest-pinned Debian trixie AMD64 image,
install its official `clang make libsqlite3-dev libjemalloc-dev libvips-dev libssl-dev`
packages, and run `make -j2 CC=clang`. Record package versions and hashes again.
Run from the archive's static `app` directory with a fresh writable `storage` directory:

```sh
PORT=4318 WORKERS=1 SPINEL_WORKERS=2 \
  BLOG_DB=/tmp/dqor-campfire-revocation/linux-candidate-run/storage/synthetic.sqlite3 \
  /work/linux-candidate-pack/campfire
ruby verify_sockets.rb http://127.0.0.1:4318 \
  /tmp/dqor-campfire-revocation/linux-candidate-run/storage/synthetic.sqlite3
ruby verify_adversarial.rb /work/roundhouse /work/once-campfire
```

For the native backpressure fixture, emit C with the pinned compiler:

```sh
spinel verify_backpressure_native.rb -I /work/roundhouse/runtime/spinel \
  -c -o backpressure-native.c
```

Then, inside the AMD64 build container, from the built retained pack directory:

```sh
clang -O2 -DSP_THREADS -DSP_INT_OVERFLOW_MODE_RAISE \
  -Ilib -Ilib/regexp -Ilib/regexp/shim /work/backpressure-native.c \
  lib/*.o lib/regexp/*.o -lm -ljemalloc -lpthread -lcrypt \
  -o /work/backpressure-native
SPINEL_WORKERS=2 timeout 10 /work/backpressure-native
```

## Remaining work

The candidate is not release-ready. Fix and revalidate connection registration versus
revocation atomically, authorization-change commit ordering (including deactivation),
and cancellation independent of blocked writers while preserving exclusive fd-close
ownership. Add full-server reconnect tests with real transaction barriers after those
changes. Keep the current failing probes as release gates; ordinary repository CI
does not run external source checkouts and does not turn their failures into passes.
Multi-process revocation, SSO/tenant authorization and production image identity remain
outside this verification. No source patch was changed to conceal any failed gate.
